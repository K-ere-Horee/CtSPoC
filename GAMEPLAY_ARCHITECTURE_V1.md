# Catch the Scott - Gameplay Architecture V1

Version: 1.0 (Vision Draft)
Date: 2026-07-18
Status: Product and architecture contract

This document defines the V1 gameplay vision and the ownership boundary
between the World device and the Rod device. It is intentionally a design
document. It does not authorize implementation work by itself.

------------------------------------------------------------------------

## Vision

Catch the Scott is a two-device fishing experience. World (Mac, iPad, and
later Vision) is the complete game experience. Rod (iPhone) is a physical
fishing controller.

The player should almost never look at the iPhone during gameplay. The Rod
should feel like a real fishing rod rather than a second game screen.

## Core Principle

> Rod is an input device. World is the game.

Every future feature must preserve this principle.

------------------------------------------------------------------------

## Device Responsibilities

### World

World owns every gameplay system and every important visual feedback surface:

- Main Menu
- Tutorial
- Calibration Instructions
- Gameplay HUD
- Fishing Scene
- Fish AI
- Hook Simulation
- Fish Result Screen
- Progression
- Future inventory, shop, and collection systems

### Rod

Rod is intentionally minimal. It owns:

- Motion input
- Calibration capture
- Cast and reel intent
- Button input
- Haptic feedback output
- Connection status

Rod must not display gameplay HUD, fish information, tutorial content,
progression, or catch results.

## Rod V1 Interface

The intended final controller interface contains only:

```text
Catch the Scott

CONNECTED

[ Start Fishing ]
[ Start Casting ]
[ Calibrate ]
[ End Fishing ]
```

"Start Casting" (ADR-045) only appears while fishing, and arms one cast
attempt at a time rather than casting always being live off ordinary phone
motion — disabled whenever the hook isn't idle. Current debug values are
temporary development tools and are not part of the final controller
experience.

------------------------------------------------------------------------

## World UI Philosophy

The player's attention belongs on World. World presents:

- Tutorial and calibration guidance
- Cast meter
- Searching and fish-interest feedback
- Bite and fight feedback
- Line tension
- Catch result
- Progression and continuation choices

The Rod remains visually quiet and communicates non-visual feedback through
haptics.

------------------------------------------------------------------------

## Gameplay Loop

```text
Launch
  -> Connect Rod
  -> Calibration
  -> Ready
  -> Start Fishing
  -> Cast
  -> Hook Flying
  -> Hook Splash
  -> Searching
  -> Fish Interested
  -> Bite
  -> Fight
  -> Catch or Escape
  -> Result
  -> Continue
  -> Cast Again
```

### Connect

World waits until Rod connects. The player cannot continue until the
controller is available.

### Calibration

Calibration instructions appear entirely in World. Rod only captures the
reference orientation and sends the calibration command/result.

```text
Hold your rod naturally.
  -> Press Calibrate.
  -> Great!
  -> Perform one cast.
  -> Calibration Complete.
```

### Ready

World enters idle fishing mode and presents the gameplay HUD. The player may
begin fishing.

### Cast

Casting itself is a natural motion (backswing distance, then a forward flick),
not a button-driven meter — but the player must press "Start Casting" first to
arm one attempt, so ordinary phone movement can never be misread as an
unintended cast. World displays the motion-driven Cast Meter using the
resolved power generated by the Rod motion system, appearing once armed. The
meter fades after launch.

### Hook Flying and Splash

The hook moves using launch direction, launch angle, and cast power. RodRoot
does not move. Splash feedback belongs to World; Rod may receive a small haptic
confirmation.

### Searching

The hook does not immediately catch a fish. World performs a searching and
fish-selection phase, with optional ripples, bubbles, and fish shadows.

### Fish Interested

A nearby fish becomes interested but has not bitten. World shows subtle
movement and Rod provides slow periodic vibration.

### Bite

The bite is a distinct event. World provides strong splash, line animation,
and tension feedback. Rod provides a strong haptic pulse.

------------------------------------------------------------------------

## Fish Fight

The fight is the core gameplay interaction. It is not a quick-time event. It
combines physical rod movement, reeling, line tension, and haptic feedback.

### Line Tension

Line tension replaces a generic health bar:

```text
LOW ---------------- HIGH
              ^
```

The player keeps tension in a safe zone. Sustained tension that is too high or
too low causes the fish to escape and may snap the line.

### Haptics

Rod haptics communicate resistance through rhythm as well as intensity:

- Weak fish: spaced taps
- Medium fish: regular taps
- Large fish: rapid repeated taps
- Extreme resistance: continuous vibration

World decides the gameplay event and Rod renders the typed feedback as haptic
output. Rod does not decide fish state.

------------------------------------------------------------------------

## Catch Result and Continue

After a successful catch, World displays:

- Fish name
- Weight
- Length
- Stars
- Coins
- New record status

Rod plays a celebration haptic. World then offers Continue Fishing or Return to
Menu.

------------------------------------------------------------------------

## Fish and Progression Systems

Each fish species owns static data:

```text
Species
  -> Weight Range
  -> Length Range
  -> Resistance Range
  -> Value
  -> Difficulty
```

Each catch creates a randomized fish instance, so two fish of the same species
may differ in weight and length.

Progression is based on equipment such as hook, bait, fishing line, and reel.
Higher-tier equipment unlocks larger fish pools and improves catch
probabilities.

Fish selection is data-driven:

```text
Biome
  -> Water Type
  -> Equipment
  -> Bait
  -> Difficulty
  -> Probability Table
  -> Selected Fish
```

## Architecture Boundary

```text
Rod
  Motion Input
      -> RodMotionInterpreter
      -> Cast Resolver
      -> Transport

World
  Transport
      -> Game State
      -> Gameplay Systems
      -> HUD
      -> Fish AI
      -> Hook Physics
      -> Visual Feedback
      -> Rendering
```

Rod owns physical movement, button input, and haptic output. World owns
gameplay, simulation, visuals, tutorials, progression, and player feedback.
This separation must not be broken.

Gameplay systems must consume shared contracts rather than reading CoreMotion
or other Rod-only implementation details. The World controller root remains
spatially attached to the player; only hook and future fishing-line gameplay
objects move through the scene.

------------------------------------------------------------------------

## V1 Success Criteria

V1 is complete when the player can experience the full loop:

- Rod connects successfully.
- Player calibrates naturally.
- Player performs a physical cast.
- Hook lands in the water.
- Fish selection begins.
- Fish may become interested and bite.
- Player reels using physical motion.
- Line tension creates meaningful gameplay.
- Dynamic haptics communicate fish resistance.
- Fish is caught or escapes.
- World displays the result screen.
- Player can immediately begin another fishing session.

## Long-Term Goal

The player's attention should remain on World. The Rod should disappear into
the player's subconscious as a physical controller, so the player feels like
they are holding a fishing rod while the game world unfolds in front of them.
